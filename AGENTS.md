# Правила работы над проектом

- Общайся с пользователем и веди проектную документацию на русском языке.
- В начале каждой задачи прочитай `plan.md`. Это источник концепции, принятых решений и текущего прогресса.
- Объём выбранного игрового этапа и критерии проверки сверяй с `ТЗ.md`.
- Перед реализацией осмотри актуальные файлы проекта: записи плана не заменяют проверку кода.
- Сохраняй основу: Godot, 3D, целевая ОС Аврора; сбалансированная база персонажа без фиксированных классов; отдельные человек с имплантами и экзокостюм.
- Экзокостюм определяет физические возможности, импланты дают способности и влияют на психику. Стиль боя возникает из их сочетания.
- Улучшения должны менять игровые решения и иметь осмысленную цену. Учитывай повреждения отдельных узлов и пилота.
- Предпочтение пользователя к тяжёлым бойцам не означает запрет лёгких сборок или старт с тяжёлого класса.
- Не выдавай предложенные механики, сюжет, названия, числа и технические решения за утверждённые. Новые существенные идеи помечай как предложения.
- Явное новое решение пользователя важнее прежнего плана: обнови соответствующий раздел и журнал решений.
- Самостоятельно решай обычные вопросы реализации в рамках согласованной задачи. Существенные изменения концепции согласовывай.
- После содержательной работы обновляй статусы задач, текущее состояние, следующий шаг и журнал работ в `plan.md`.
- Используй статусы: `TODO`, `IN_PROGRESS`, `BLOCKED`, `DONE`. Для блокировки укажи причину, для завершения — результат и проверку.
- Не отмечай реализацию завершённой после одного обсуждения или написания документа. Отделяй утверждение идеи, реализацию и проверку.
- Записывай реально выполненные проверки и их ограничения. Не утверждай совместимость с Авророй без проверки на целевой платформе.
- До выбора версии Godot, языка, рендера и способа сборки проверь доступный путь запуска на целевом устройстве с Авророй.
- Источник порта — savegame/godot; пользователь указал v3.5.1-stable-sailfish-3 (подробности в `plan.md`). Не подменяй его обычной сборкой или другой основной версией Godot без явного решения; код и ресурсы должны соответствовать выбранной версии.
- Пользователь открывает отдельный чат проекта для каждой новой задачи. Выполняй задачу текущего чата, а следующий шаг фиксируй в `plan.md` для будущего чата.
- Делай проверки соразмерно изменению; не создавай игровые тесты для одних правок документации.
- При завершении задачи кратко сообщи результат, проверки и оставшиеся ограничения.

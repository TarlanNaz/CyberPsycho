# Проверка интерфейса и обучения

Сценарий `ui_check.gd` запускает настоящую парковку в Windows-сборке указанного порта Godot 3.5.1. Создаёт снимки меню, справки, диалога, паузы и поражения в этой папке. Снимки — результаты проверки, игровые сцены их не используют. Папка исключена из импорта Godot через `.gdignore`.

Запуск из корня проекта в PowerShell (путь к редактору заменить при необходимости):

```powershell
$process = Start-Process -FilePath 'C:\Users\Honor\Downloads\godot.windows.opt.tools.x64.exe' -ArgumentList '--path . --no-window -s checks/ui_check.gd' -WindowStyle Hidden -Wait -PassThru -RedirectStandardOutput checks/run.log -RedirectStandardError checks/errors.log
Get-Content checks/run.log
Get-Content checks/errors.log
$process.ExitCode
```

Результат 2026-11-19: 26 проверок PASS, `UI_CHECK_FAILURES=0`, код завершения 0, сообщений об ошибках движка нет. Просмотрены все пять снимков при 960×600.

Проверяются остановка мира в меню и паузе, четыре отдельных направления через программный ввод клавиш и через сенсорный стик, незачёт неверного направления, остальные переходы обучения, ожидание врага, блок и контратака, сброс двух пальцев без атаки, ожидание отпускания клавиш после паузы, пропуск обучения, оба исхода после анимации, повтор с восстановленным здоровьем, возврат в меню и перезапуск обучения с первого диалога.

Это программная проверка. Поворот и боевые действия частично вызываются через методы бойцов; касания подаются в обработчик стика. Она не заменяет ручное прохождение, проверку системного ввода и компоновки на реальном устройстве с Авророй. Другие пропорции экрана и аппаратная производительность не проверены.
